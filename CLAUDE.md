# CLAUDE.md — Bootstrap 5.2

## Overview

Bootstrap is a front-end CSS/JS framework (v5.2.3). Vanilla JavaScript — no jQuery dependency. Peer dependency on `@popperjs/core` for positioned components (dropdowns, tooltips, popovers).

## Repository Structure

```
scss/           # SASS source files (components, mixins, utilities, variables)
js/src/         # JavaScript ES module source (12 components + DOM/util helpers)
js/tests/       # Jasmine unit tests, integration tests, visual tests
dist/           # Compiled output (DO NOT EDIT — auto-generated)
site/           # Hugo-based documentation site
build/          # Build scripts (Rollup config, PostCSS, version management)
.github/        # Contributing guidelines, PR/issue templates
nuget/          # NuGet package config
```

## Essential Commands

```bash
npm run dist          # Build CSS + JS
npm run css           # Full CSS pipeline (compile → prefix → RTL → minify)
npm run js            # Full JS pipeline (compile → minify)
npm run lint          # Run all linters (ESLint + Stylelint + lockfile)
npm run js-test       # Run JS unit tests (Karma + Jasmine)
npm run test          # Full suite: lint + build + test + docs
npm start             # Watch mode + docs server on port 9001
npm run docs-serve    # Hugo docs dev server only
```

## Code Style & Conventions

### JavaScript (`js/src/`)
- **No semicolons**
- 2-space indentation
- Strict mode
- ES2022 syntax, ES module imports with `.js` extensions required
- ESLint config: xo base + import/unicorn plugins (`.eslintrc.json`)
- No `console.log` in source

### SCSS (`scss/`)
- Stylelint config: `stylelint-config-twbs-bootstrap` (`.stylelintrc`)
- Dollar variables must have `!default`
- Disallowed shorthand: `border-radius`, `transition` (use mixins instead)
- No `border: none` (use `border: 0`), no `outline: none` (use `outline: 0`)
- No `calc()`, `lighten()`, or `darken()` — use CSS custom properties / color-mix

### General
- UTF-8, LF line endings, 2-space indent, trailing newline (`.editorconfig`)
- Commit messages: imperative mood, reference issues when applicable

## Architecture

### JS Component Pattern
All components extend `BaseComponent` and follow this pattern:
- Constructor accepts element + config object
- Static methods: `getInstance()`, `getOrCreateInstance()`
- Event handling via `EventHandler` (`js/src/dom/event-handler.js`)
- Config via `Config` base class (`js/src/util/config.js`)
- Data storage via `Data` (`js/src/dom/data.js`)
- jQuery plugin registered via `defineJQueryPlugin()`

Key DOM/util modules:
- `dom/event-handler.js` — event binding/delegation
- `dom/manipulator.js` — attribute/property access
- `dom/selector-engine.js` — query selector wrapper
- `util/backdrop.js` — modal/offcanvas backdrop
- `util/focustrap.js` — focus trapping
- `util/sanitizer.js` — HTML sanitization for tooltips/popovers
- `util/scrollbar.js` — scrollbar width detection
- `util/swipe.js` — touch gesture support

### SCSS Layer Order (bootstrap.scss)
1. Functions → Variables → Maps → Mixins → Utilities (config)
2. Root → Reboot → Type → Images → Containers → Grid (base)
3. Component partials (forms, buttons, nav, cards, modals, etc.)
4. Helpers → Utility API generation

### Build Pipeline
- **CSS**: Sass → Autoprefixer → RTLCSS → CleanCSS
- **JS**: Rollup + Babel → Terser (UMD, ESM, and bundled-with-Popper variants)

## Testing

- **Framework**: Jasmine 5.1 via Karma 6.4
- **Coverage minimum**: 90% (statements, functions, lines), 89% (branches)
- Tests live in `js/tests/unit/*.spec.js`
- Include unit tests for any JS changes
- Run `npm run js-test` before committing JS changes

## Critical Rules

1. **Never edit files in `dist/`** — they are generated by the build
2. **Edit source only**: `scss/` for styles, `js/src/` for scripts
3. **Run `npm run lint` before committing** to catch style violations
4. **Run `npm run test` for full validation** (lint + build + test + docs)
5. **Browser support**: see `.browserslistrc` (>=0.5%, last 2 versions, Chrome/Firefox >=60, iOS/Safari >=12, no IE)
6. **Accessibility**: preserve `:focus` styles, use WAI-ARIA attributes, maintain WCAG color contrast

## Output Artifacts

CSS: `bootstrap.css`, `bootstrap.min.css`, `bootstrap.rtl.css`, plus grid-only, utilities-only, and reboot-only variants.
JS: `bootstrap.js` (UMD), `bootstrap.esm.js` (ESM), `bootstrap.bundle.js` (UMD with Popper). All have minified + sourcemap versions.

## Documentation

Hugo-based site in `site/`. Content in `site/content/docs/`, templates in `site/layouts/`. Run `npm run docs-serve` for local preview on port 9001. Markdown with custom Hugo shortcodes. Search via Algolia DocSearch.
